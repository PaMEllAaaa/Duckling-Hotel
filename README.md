# Duckling Hotel 🦆🏨

**Course:** 2110503 Software Development Practice  
**Project:** Hotel Booking

Welcome to the **Duckling Hotel** repository! This project is a comprehensive hotel booking and management system designed to facilitate seamless reservations for users and efficient management tools for administrators.

## 📋 Core Functional Requirements

### User Authentication & Accounts
* **Registration:** Users can register by specifying their name, telephone number, email, and password.
* **Login/Logout:** Registered users can securely log in using their email and password, and log out when finished.

### User Booking Management
* **Create Booking:** Registered users can book a stay for up to **3 nights** by specifying the desired dates and selecting a preferred hotel from the provided list.
* **Hotel Information:** Users can view hotel details including the hotel name, address, and telephone number.
* **Manage Bookings:** Users have full control over their reservations with the ability to **view, edit, and delete** their own hotel bookings.

### Admin Management
* **Global Booking Access:** Administrators have elevated privileges to **view, edit, and delete** *any* hotel bookings within the system.

---

## ⭐ Extra Credit Features

This project includes advanced features beyond the basic requirements to enhance the system's functionality:

### 1. Advanced Hotel Management (Admin)
* Admin can **create** new hotels by providing the hotel name, address, telephone number, and available services.
* Admin can **view** comprehensive hotel information.
* Admin can **edit** a hotel's telephone number and its list of services.
* Admin can **delete** any hotel from the system.

### 2. Service Capacity Management
* **Admin Controls:** Admin can **create, view, edit, and delete** distinct hotel services, assigning a specific daily capacity to each (e.g., fitness, breakfast, swimming pool, sauna, karaoke room).
* **User Selection:** When booking, users can select up to **2 services** provided by the hotel. The system enforces capacity limits, preventing users from selecting a service if it is fully booked on any day during their intended stay.

### 3. Issue Reporting System
* **User Reports:** Registered users can **create** a stay-related issue report directed to the admin. This must be submitted within 1 month after their check-out date.
* **User History:** Users can **view** their personal history of submitted reports.
* **Admin Moderation:** Admins can **view** all issue reports submitted by users and have the authority to **delete** reports from the system.
